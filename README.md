# 幕间 · Interlude

一张属于跑团同伴的桌子。支持 **D&D 5e（2014 / SRD 5.1）** 和 **CoC 第 7 版** 的角色、骰子、检定与共同叙事；不模拟游戏世界或替主持人裁定。

## 本地运行

需要 Node.js 22.12+（建议 Node.js 24 LTS）。

```sh
npm ci
cp .env.example .env
npm run dev
```

打开 **http://127.0.0.1:5173**。Vite 将 Socket.IO 与 `/api` 请求转发到 `127.0.0.1:3001`。用另一个浏览器或无痕窗口可以验证第二名参与者；同一浏览器的普通标签页会恢复同一身份。

```sh
npm test         # 规则单测与真实 Socket 集成测试
npm run build   # TypeScript 检查及生产构建
npm start       # 同一个 Node 服务提供前端、API 和 WebSocket
```

生产构建后地址默认为 http://127.0.0.1:3001。修改 `.env` 后重启服务。项目中的字体随构建一起提供，无需访问外部字体服务。

## 使用流程

1. 先选择规则，然后创建房间或用 6 位房间码加入，最多 8 人。
2. 创建者成为 DM / KP，可选择「房内演绎」或「外部演绎」。房间码选择的规则必须与房间一致。
3. 主持人先设置本团制卡范围；玩家新建、导入或载入人物卡，完成技能分配并提交主持人审核。草稿可先保存，分配合规后才能准备。至少一位玩家、所有成员在线且准备、每位玩家的当前人物卡通过当前规则版本审核后，主持人才可开始。主持人同样需要准备，但不能给自己的主持人席位载入玩家卡。
4. 随时使用快速骰子、自定义表达式、规则检定、角色状态和物品工具。主持人可以暗骰、公布场景、给予物品、调整角色资源与管理行动顺序。故事开始后，打开「角色调整」选择一名玩家角色，即可修改属性／技能的长期数值，或添加能停用、移除的临时效果。
5. 房内演绎支持所有人的公开文字叙事与图片消息；外部演绎只保留记录与辅助工具。主持人返回准备阶段后可切换模式、调整成员或移交主持人。

深浅主题自动保存；手机上的「圆桌与记录」「局内工具」「同桌伙伴」可分别切换。席位围绕桌面均匀分布。

入房前可从主侧边栏的「主持人工具集」制作 NPC／怪物资料。CoC 制卡时，职业点与兴趣点总览滚出视野后会显示剩余点数浮窗，数值随分配即时更新；点击浮窗箭头返回总览。

## 角色卡与规则范围

- 姓名、职业、背景、技能分配等手填字段有明确提示；属性可无限重掷，原创故事词条可无限刷新并手改。
- CoC 的「属性与状态」页可启用属性点上限，限制八项属性总和（不含幸运），个人设置支持 195–720。房间内若主持人规定了总和范围，直接锁定使用主持人的上限，个人偏好不影响本房间。超限卡可按比例降低（逐项向下取整到 5 的倍数，保留幸运）或重掷；两种操作均检查本桌属性范围。降低后须复核技能分配；无解时提示并保留草稿。个人设置会在当前浏览器记住，导入及修改上限不会自动改写卡片。
- D&D：4D6 取最高三枚生成六项基础属性，支持 SRD 5.1 的 12 个职业。职业技能、背景两项技能、种族熟练、重复来源的替代项、主持人额外名额与专精都有分配记录；技能加值和职业豁免由属性、熟练与专精计算。种族属性加值、其余职业特性、法术、升级、生命上限和装备效果仍由使用者核对填写。
- CoC：支持 11 个职业的八项技能选择、各自职业点公式、INT×2 兴趣点与信用区间。技能百分比由基础值加两类分配点数计算，默认信用可以使用职业或兴趣点。KP 可关闭“允许兴趣点投入职业技能（含信用评级）”，执行专点专用；关闭后兴趣点只用于非职业技能，已有不合规投入由玩家在制卡器中点击“退回职业技能上的兴趣点”再分配。建议分配与服务端审核同样遵守此开关。默认允许不分完，但余点不会自动作为局内成长点保留；主持人可要求全部分完。医生的生物学、药学独立记录；神话技能默认须为 0，例外由主持人明确允许。百分骰、奖励／惩罚骰、理智与 HP / MP / SAN 工具可在局内使用；年龄修正、伤害加值和移动仍需核对规则书。
- JSON 与 Markdown 都含完整的版本化结构；本应用导出的 Markdown 内附 JSON 数据块，可原样重新导入。导入检查规则、版本、字段类型、数值边界及危险对象键名。
- 角色档案位于当前浏览器的 `localStorage`，不会跨设备自动同步。房间中的角色另由服务端保存；状态或物品改变后，可从「我的角色」导出最新版本。切换设备前请导出备份。
- 主持人可限制单项属性、技能、属性总和、职业／种族及额外熟练名额；手填数值同时受文件格式边界和房间范围约束。默认 D&D 人物属性 1–20、CoC 人物属性 1–99、CoC 技能上限 99；需要扩展时由主持人设置具体范围。
- 完整人物卡保存，以及准备阶段的资源／物品修改，会清除该卡的准备与审核。制卡规则更新、返回准备阶段、主持权移交或继任会要求重新审核；服务端使用人物卡版本与规则版本检查，过期审批不能开启故事。正式演出中玩家可调整自己的资源与物品，主持人还可修改玩家属性和技能。

## 局内角色调整

在房间工具栏打开「角色调整」，或点选同桌伙伴后选择「调整属性与技能」。选择角色，再点属性或搜索技能：

- **长期数值**：填写期望数值，例如 CoC 侦查成长为 60；可注明原因、重置此项调整。原始制卡记录和分配点数仍保留，不会因剧情成长重新消耗制卡点。
- **临时修正**：填写正负修正、效果名称和可选结束条件，例如侦查 +15、下一次休息后结束。多个已启用效果相加，可以逐个停用、重新启用、移除或清除全部。
- 面板同时显示原始、长期、生效三种数值。D&D 技能仍随关联属性、熟练与专精计算，再叠加技能修正；填写长期技能值时不计临时属性效果。CoC 技能直接改变检定目标及困难／极难阈值。
- 只有主持人能在故事进行中操作，玩家从「角色数值」查看。服务端检查权限、版本与总值边界，变更公开记入房间日志。其他窗口改过角色时，草稿会保留并要求载入最新数值。
- 调整随房间保存，JSON／Markdown 导出也包含完整修正记录；导入卡片或返回准备阶段后仍要重新审核，审核页会展示长期与临时修正。

临时效果**不会自动到期**，请主持人依结束条件手动停用或移除。这里仅记录固定数值；不自动应用法术、状态、骰式加成，也不自动修改 HP／MP／SAN 上限或 AC。敏捷修正用于下一次排定先攻，不改写已经排好的顺序。详见[局内调整说明](docs/CHARACTER-ADJUSTMENTS.md)。

详见 [规则与格式说明](docs/RULES.md)。参考资料：[AgnesSummer/TRPG](https://github.com/AgnesSummer/TRPG)、[D&D SRD](https://www.dndbeyond.com/srd)、[Chaosium 官方资料](https://www.chaosium.com/call-of-cthulhu-resources/)。参考仓库中的 DND 3R 资料没有混入 5e 计算。

## CoC 主持人卡库

KP 使用独立的 NPC／怪物资料卡，支持原创示例、空白分类模板、手填、属性骰式和批量 JSON／Markdown 导入导出。卡库不消耗调查员职业／兴趣点，也不套用普通玩家卡的属性上限；未知或不适用的属性可以为空。攻击、护甲、伤害加值、移动、特殊能力与理智损失由 KP 按模组填写和裁定。

模板中的路人、联络人与「雾岸猎影」是本项目原创示例；神话生物、神祇、传统恐怖生物、野兽等分类参考 [Chaosium Bestiary](https://cthulhuwiki.chaosium.com/bestiary/)，空白分类不含官方怪物数值，也没有自动平衡等级。官方数值须查阅有权使用的规则书或模组。

「主持人工具集」中的个人备团库可在入房前使用，以 IndexedDB 保存在当前浏览器，最多 200 张卡。刷新、换房间不会清空；它不会自动上传。担任相应规则房间的 KP／DM 后，可将单卡或全部资料带入房间，也可将房间用卡存回个人库。每次传递都会生成独立副本，避免局内修改覆盖备团原稿。跨浏览器或设备使用前请导出备份。

每个房间最多保存 200 张卡，单次导入与保存上限 8 MiB，大文件可拆批保存。房间卡库只发给当前主持人，随主持权移交并支持服务端存档恢复；玩家与旧主持人的后续快照无法取得卡库。主持人升任前已有的玩家卡会保留，主持期间不作为玩家人物卡使用。两种规则使用独立卡库与文件格式，不混用。

工具集中提供可复制的 LLM 提取提示词、可直接导入的 Markdown 模板及文字教程。将提示词和外部剧本交给自己选择的 AI Agent，得到 `keeper-source` 资料后直接导入；编号和时间戳由网站生成，未知值保持空白，不自动掷骰或用属性覆盖模组 HP。详见 [剧本提取与导入教程](docs/KEEPER-IMPORT.md)、[Markdown 模板](docs/templates/keeper-import.md)和[完整提示词](docs/templates/keeper-extraction-prompt.md)。

## D&D 数据块与本场战斗

D&D 备团库采用独立的 Stat Block 格式，记录 AC、HP、生命骰、速度、六项属性、豁免、技能、抗性／免疫、感官、语言、CR／XP，以及特性、动作、反应、施法和传奇／巢穴能力。它不受玩家制卡分配机制限制。未提供的数值留空，固定 HP 与生命骰分别保留，不自动估算 CR、补满 HP 或重算模组数据。

可在入房前制作、保存、复制和批量导入；个人 D&D 库最多 200 张，总量 8 MiB。网站提供[数据块教程](docs/DND-STATBLOCKS.md)、[Markdown 模板](docs/templates/dnd-import.md)与[LLM 提取提示词](docs/templates/dnd-extraction-prompt.md)。

房间右侧的「场景与回合」包含场景设置和「行动与状态」。从房间卡库生成的 NPC／怪物个体各自记录 HP、公开名称、状态与资源次数；不会修改备团模板。玩家 HP 与原角色卡同步。主持人可排定回合、公开个体名称和状态，完整 NPC 资料始终保留在主持人端。

D&D 提供攻击检定、临时 HP、专注与死亡豁免记录、能力次数和充能骰；CoC 提供 DEX 顺序、已准备枪械修正、重伤／濒死标记，以及闪避／反击的近战对抗比较。骰点由服务器产生，效果由主持人确认；攻击、伤害与对抗不会自动扣血。详见[战斗辅助操作说明](docs/COMBAT.md)。

## 地图册与场景集

「主持人工具集 → 地图与场景」提供入房前的个人地图集：手动创建地图册，添加多个地图及场景，或将内置提示词和外部剧本交给其他 AI Agent，导入生成的 Markdown / JSON。地图记录布局、路线与地点描述，不生成战棋图片。可不设地图，仅整理独立场景。

个人库与房间库各最多 50 本、8 MiB；每本最多 50 张地图、300 个场景。导入按整批校验，作为独立副本保存。原稿位于浏览器 IndexedDB，可导出备份；房间资料随服务端房间保存，只有当前主持人可读取。主持权移交后由新主持人接手。

从个人地图集点击“带入房间”，或直接在房间“地图与场景”导入资料。通过目录、地图筛选和搜索快速选择场景，核对预览后点击“公布此场景”。只发布标题与公开描述；地图布局、来源和主持人笔记保留在私密库。请先核对 AI 是否把秘密写进公开描述。

详见[地图集教程](docs/ATLAS.md)、[Markdown 模板](docs/templates/atlas-import.md)和[LLM 提取提示词](docs/templates/atlas-extraction-prompt.md)。

## 图片消息与存储目录

故事开始后，在房内聊天区点击“添加图片”，或向输入框粘贴图片。选择后会显示预览，可移除或附带文字再发送。支持 PNG、JPEG、GIF、WebP，单张最多 8 MiB；失败时保留发送草稿。聊天中点击图片可查看原图，也可单独下载。图片与文字受相同的房内演绎和开始状态限制。

直接运行时在 `.env` 配置 `IMAGE_DIR=/你的/图片目录`，不配置则使用 `DATA_DIR/images`。相对路径基于进程工作目录。修改后重启服务，目录须允许运行服务的账号读写。改目录时需将旧图片一并迁移，否则旧记录会显示图片占位符；保留 `DATA_DIR/images.json` 才能继续验证原图片引用。

Docker Compose 内部使用 `/app/images`，默认挂载独立的 `image-data` volume。可在 `.env` 设置 `IMAGE_STORAGE_PATH=/宿主机/图片目录` 替换为自定义路径；该目录需对容器内的 node 用户（UID 1000）可读写。原生 `IMAGE_DIR` 和 Docker 的宿主机挂载路径是两种运行方式的设置。

图片使用随机文件名，不使用上传文件名拼接磁盘路径；上传需要有效成员身份，读取也仅限仍在本房间的成员。API 检查文件大小、格式与图片签名，不接受 SVG / HTML。图片不会发送给 Gemini。反向代理须允许至少 12 MiB 的请求体（例如 Nginx / OpenResty 的 `client_max_body_size 12m`，用于图片的编码传输）。

服务端保留完整可用记录；页面先显示最近 300 条，可加载更早记录。图片在最后一次游玩结束（返回准备、关闭房间或全员离线）14 天后自动删除；再次开团续期，正在游玩的图片不会清理。每分钟检查，停机期间到期的图片启动时清理；此期限独立于房间的 7 天清理。查看图片、预览或导出存档不续期。备份时同时保存 `DATA_DIR`（包括 `images.json`）与图片目录。全局 ZIP 默认保留服务端路径引用，不携带或下载图片文件；关闭图片开关后使用文字描述。删除或不可用的图片在续团后显示占位符。

## 房间配置导入与导出

主持人打开桌边“房间配置”，可导出 JSON 或 Markdown，包含房名、规则、演绎方式、全部制卡要求（含点数开关与属性上限）和当前公开场景。文件可在新房间创建页选择“从配置文件创建”，也可在已有房间的准备阶段导入。

导入先展示预览，经“应用配置并重新审核”后一次性生效。规则必须匹配；旧准备和审核结果清除，所有成员重新准备，玩家人物卡重新审核。故事进行中只允许导出。并发修改会提示先核对最新配置。

配置不会包含房间码、成员、凭证、人物卡、聊天记录或私密备团库；NPC／怪物和地图集各自导入导出。新建房间会生成新的身份与房间码。

## 全局存档与续团

主持人在房间「全局存档」中导出含配置、角色、修正、备团资料、遭遇进度与完整可用记录的 ZIP。图片开关默认开启，只保留路径引用；关闭时须填写替代描述。支持的浏览器可以选择保存文件夹；其他浏览器使用下载方式并提供路径设置指引。

下次选择相同规则，在「创建房间 → 从全局存档续团」中导入 ZIP，核对后恢复原阶段。新房间重新生成凭证，每位玩家凭主持人单独提供的一次性席位恢复码回到原角色。旧版本已经丢弃的记录无法补回；界面会明确提示。详见[全局存档与续团教程](docs/SESSION-ARCHIVE.md)。

## Gemini 灵感小窗

在 `.env` 配置并重启：

```dotenv
GEMINI_API_KEY=你的服务端密钥
GEMINI_MODEL=gemini-3.8-flash
```

使用 [Gemini Generate Content API](https://ai.google.dev/gemini-api/docs/text-generation)，模型可按 [官方模型列表](https://ai.google.dev/gemini-api/docs/models)调整。默认不开启，没有密钥时界面明确提示，不伪造 AI 结果。

只有主持人点击生成时才请求 Gemini。发送内容为当前场景、角色姓名与职业、最近 12 条公开叙事和主持人本次问题；不发送会话凭证、暗骰或完整角色笔记。回答分为「剧情建议」和「示例旁白」，只在主持人窗口显示，不会自动发到公共记录。每个主持人至少间隔 10 秒请求，具有超时和异常处理。密钥只在服务器使用。

## 持久化与身份

- 房间状态原子写入 `DATA_DIR/rooms.json`（默认 `./data`），重启后支持凭证续连。保存文件权限为 `0600`；备份这个目录可保留房间。
- 会话凭证使用随机 256 位令牌；只发给该成员，并保存在其浏览器。房间广播不包含任何人的凭证。主持人权限、状态修改和暗骰过滤均在服务器校验。
- 关闭页面会保留座位；点「离开房间」才释放座位。主持人主动离开后，交由在线成员接任并返回准备阶段；没有其他在线成员则关闭房间。
- 房间在演出期间不接受新成员，已有成员可以重连。准备阶段主持人可移出离线成员。
- 每间房间保留完整可用记录，页面先显示最近 **300 条**并提供历史加载；Markdown 导出已载入部分，全局 ZIP 导出全部。默认最多 200 间房间，离线且 7 天未活动的房间会清理。适合单实例小型站点；多实例部署需要共享存储与 Socket.IO adapter。
- 玩家人物资料及笔记对同房间成员可见。暗骰的投掷行为与骰式 / 检定名称可见，点数和结果显示“？”；实际结果、灵感结果和独立 NPC／怪物卡库私密。房间码用于邀请，勿公开分享不希望陌生人进入的房间码。

## 部署

提供 Dockerfile 与 Compose 配置：

```sh
cp .env.example .env
docker compose up -d --build
```

默认仅在宿主机 `127.0.0.1:3001` 监听，便于由 Nginx / OpenResty 反向代理并配置 HTTPS。代理须支持 WebSocket Upgrade，`proxy_read_timeout` 至少 75 秒。`ALLOWED_ORIGINS` 可填实际站点的完整来源（多个用英文逗号分隔），例如 `https://trpg.example.com`。容器内服务监听 `0.0.0.0`，房间保存在独立的 `room-data` volume。

现有代码不会自动创建公网域名、配置证书或部署到远程服务器。部署后分别检查 HTTP 健康接口 `/api/health`、WebSocket 多人同步和重启续连。

## 浏览器验收

`tests/e2e.py` 用两个隔离浏览器上下文测试完整 D&D / CoC 流程、主题、导入导出、角色检定、状态与物品、暗骰隔离、断线恢复、外部演绎以及 390px / 320px 布局。

`tests/e2e_review.py` 补充验证 KP 私密资料库的批量制作与文件复用、CoC 点数分配、主持人审核与退回、单项剧本范围、旧审批失效、旧卡分配迁移和手机上的长表单。

`tests/e2e_toolkit.py` 验证个人卡库在入房前制作、文件下载与复制、示例模板导入、刷新恢复、房间副本隔离、CoC 浮窗与 D&D 标签布局。

`tests/e2e_encounter.py` 验证 D&D 数据块、提取文件与持久化、独立参战个体、玩家 HP 双向同步、公开与私密信息、主持人确认检定、CoC 近战对抗和窄屏布局。

`tests/e2e_adjustments.py` 验证主持人选择角色、长期数值和临时效果、玩家检定同步、并发草稿保护、重连与导出、再次导入审核、战斗检定默认值及深浅主题和手机布局。

`tests/e2e_preparation.py` 验证地图模板导入、多场景持久化与公开／私密隔离、CoC 专点专用、房间配置导入导出、双方图片消息、失败重试与手机布局。

`tests/e2e_archive.py` 验证审核状态对齐、暗骰遮罩、实际 ZIP 下载、默认图片开关与路径引用、图片描述、保存位置 API 的写入 / 取消分支、导入预览、席位认领、恢复原图、历史加载及 320 / 390px 布局。传入测试服务器的 `--image-dir` 后，还会删除本脚本上传的测试图片，验证恢复后的占位符与深浅色布局；请仅用于隔离测试环境。文件夹选择器在无头测试中使用 API 替身；真实系统弹窗取决于浏览器和权限。

`tests/image-lifecycle.test.ts` 与 `tests/server-archive.test.ts` 用可控时钟验证 14 天边界、游玩续期、活跃图片保护、多个房间引用、重启清理、旧房间迁移、房间先过期时的独立保留，以及过期 / 伪造引用不可恢复原图。

```sh
python3 -m venv .venv
.venv/bin/pip install -r tests/requirements.txt
.venv/bin/playwright install chromium
.venv/bin/python tests/e2e.py
.venv/bin/python tests/e2e_review.py
.venv/bin/python tests/e2e_toolkit.py
.venv/bin/python tests/e2e_encounter.py
.venv/bin/python tests/e2e_adjustments.py
.venv/bin/python tests/e2e_preparation.py --url http://127.0.0.1:3001
.venv/bin/python tests/e2e_archive.py --url http://127.0.0.1:3001
```

原生 IndexedDB 的容量、跨页并发和失败回滚检查需运行 Vite，然后执行 `.venv/bin/python tests/e2e_keeper_storage.py`。脚本优先使用本机 Chrome，没有时使用 Playwright 安装的 Chromium；也可用 `--chrome` 指定可执行文件。
