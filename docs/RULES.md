# 规则口径与人物卡格式

本工具辅助制卡、掷骰、记录和主持裁定。首版选择 **D&D 5e（2014，SRD 5.1）**与 **Call of Cthulhu 第 7 版**。它没有实现完整战斗引擎、法术数据库、冒险模组或自动主持。

用户提供的 [AgnesSummer/TRPG 资料仓库](https://github.com/AgnesSummer/TRPG)可用于查阅中文资料；其中 DND 目录主要是 3R/3.5 资料，不能与本工具的 5e 数值混用。CoC 目录中的核心规则书和调查员手册用于核对第 7 版术语。网站不打包、转载这些完整书籍。

## D&D 5e（2014）

依据：[SRD 5.1 官方 CC 版本](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf)。

| 项目         | 本工具行为                                                 |
| ------------ | ---------------------------------------------------------- |
| 初始六项属性 | 每项投 4d6，丢弃最低一颗后求和；允许无限重掷和手动调整     |
| 属性调整值   | `floor((属性 − 10) / 2)`                                   |
| 熟练加值     | 1–4 级 +2；5–8 级 +3；9–12 级 +4；13–16 级 +5；17–20 级 +6 |
| 属性检定     | d20 + 属性调整值 + 临时修正                                |
| 技能／豁免   | 属性调整值、对应熟练加值与临时修正相加；熟练只加一次       |
| 优势／劣势   | 投两颗 d20，分别取高／低；普通投一颗                       |
| 攻击检定     | d20 + 手填的完整攻击加值；自然 20 重击，自然 1 自动失手    |
| 其他检定     | 根据总值是否达到 DC 判断；自然 1、20 不自动改变结果        |

姓名、族裔、背景文字、等级和其他身份资料由玩家填写。属性骰尚未计入族裔增益；请按选择的族裔自行调整。制卡器支持 SRD 5.1 的 12 个职业，按职业可选范围与数量记录技能熟练，并计算职业豁免。背景选择两项技能；精灵固定察觉、半兽人固定威吓、半精灵自选两项技能。来源重复时须另选相同数量的替代熟练，额外技能和豁免只能使用主持人给定名额。

技能专精只能选已熟练技能，并受职业等级名额限制：游荡者 1 级最多两项、6 级最多四项；吟游诗人 3 级最多两项、10 级最多四项。专精使用两倍熟练加值；吟游诗人 2 级起未熟练技能使用向下取整的半熟练加值。职业技能加值由属性、熟练和专精自动计算，不允许脱离分配记录自由填写。法术、装备、其他职业特性和情境加值仍由 DM 核对。

新卡的 HP 使用 **8 + 体质调整值**作为待校正的占位值，AC 使用无甲 **10 + 敏捷调整值**。请按职业生命骰、等级、升级方式、护甲和盾牌填写最终 HP 上限及 AC。选择职业本身不会自动修改它们。D&D 不使用本卡模型中的 MP、SAN 字段；死亡豁免在「场景与回合 → 行动与状态」中单独记录。

## CoC 7

官方入门资料：[Chaosium Quick-Start](https://www.chaosium.com/cthulhu-quickstart/)。以下是本工具的计算范围，完整裁定仍请使用本团的第 7 版规则书。

| 项目                          | 本工具行为                |
| ----------------------------- | ------------------------- |
| STR、CON、DEX、APP、POW、幸运 | `3d6 × 5`                 |
| SIZ、INT、EDU                 | `(2d6 + 6) × 5`           |
| HP 上限                       | `floor((CON + SIZ) / 10)` |
| MP 上限                       | `floor(POW / 5)`          |
| 初始 SAN                      | POW，不超过 SAN 上限      |
| SAN 上限                      | `99 − 克苏鲁神话技能`     |
| 闪避／母语的初始值            | `floor(DEX / 2)`／EDU     |

幸运、HP、MP、SAN 的基础定义可查阅 [Chaosium 副属性说明](https://callofcthulhuwiki.chaosium.com/investigators/step-two-secondary-attributes.html)；闪避、母语及技能基值的使用可查阅 [Chaosium 职业和技能说明](https://callofcthulhuwiki.chaosium.com/investigators/step-three-occupation-and-skills.html)。

制卡器支持古物学家、作家、记者、私家侦探、医生、教授、警探、艺术家、神职人员、军人和考古学家 11 个职业。每个职业选择八项职业技能，职业点使用对应的 EDU×4 或 EDU×2 加职业允许属性×2 公式；兴趣点为 INT×2。职业点只投向所选八项技能及信用，兴趣点可投向其他技能及信用；信用的最终值仍必须落在职业区间内。**最终百分比 = 基础值 + 职业点 + 兴趣点**，不能通过直接修改最终值绕过账本。

医生的科学（生物学）与科学（药学）、拉丁语等使用独立字段；泛用艺术／手艺、科学、外语的具体专长仍应写入笔记。职业技能槽参考 [Chaosium 官方职业示例](https://callofcthulhuwiki.chaosium.com/investigators/step-three-occupation-and-skills.html)。本工具采用点数账本，不采用该官方入门页的固定百分比分配法。新调查员的克苏鲁神话默认必须为 0；主持人允许例外后，也须保留分配来源并按神话技能重算 SAN 上限。

职业点和兴趣点分别检查超支。默认允许不分完，未分配点数不会自动作为局内成长点保留；KP 可以要求制卡时全部用完，也可以设置技能和属性范围。建议分配优先用职业点满足信用下限，并受本团上限限制，不能保证满足每一组自定义限制。年龄属性扣减、教育成长检定、年轻调查员的幸运处理、体格、伤害加值、移动力、重伤、疯狂发作及成长检定仍由 KP 裁定和记录。

CoC 检定比较 1–100 的百分骰与目标：不超过完整目标为普通成功，不超过向下取整的二分之一／五分之一为困难／极难成功；1 为大成功。目标低于 50 时，96–100 为大失败；目标至少 50 时，100 为大失败。奖励骰／惩罚骰会**保留同一颗个位骰，只多投一颗十位骰**，然后选更好／更差的完整百分骰结果；十位 00 与个位 0 组合表示 100。依据：[Chaosium Quick-Start 中的检定和奖励／惩罚骰](https://www.chaosium.com/content/FreePDFs/CoC/CHA23131%20Call%20of%20Cthulhu%207th%20Edition%20Quick-Start%20Rules.pdf)。

普通理智检定使用人物卡**当前 SAN**，掷普通百分骰，只报告成功或失败，不沿用技能检定的困难／极难等级或奖励／惩罚骰。理智损失及后续状态由 KP 判断，依据：[Chaosium 官方理智规则](https://cthulhuwiki.chaosium.com/rules/sanity.html)。自我治疗等特殊规则请由 KP 另行裁定。其他检定的所需难度、对抗胜负、孤注一掷和攻击伤害仍由 KP 判断。没有人物卡的主持人可输入目标百分比代投 NPC 检定。首版技能／属性检定支持一颗奖励／惩罚骰；不实现多颗奖励／惩罚、幸运消耗和自动损失。

## 建卡限制与审核

房间建卡规则由当前主持人设置，支持单项属性、技能、八项／六项属性总和、当前资源与上限、年龄／等级等该规则适用字段，以及职业／种族允许列表。CoC 属性总和不含幸运。重复字段、未知字段、混入另一规则的字段以及下限大于上限的范围都会被拒绝。D&D 的技能、额外豁免和专精还必须有合法来源，单纯提高数值范围不会增加来源名额。

普通人物卡的录入边界与房间制卡范围分开校验：文件中 D&D 属性允许 1–30、CoC 属性允许 1–100，但房间默认分别为 1–20、1–99。CoC 技能默认上限 99，主持人可按单项范围明确允许 100；这仍不能突破普通人物卡字段格式的上限。扩大范围、指定职业／种族或允许初始神话均须由主持人明确配置。

姓名与职业仍需填写；尚未完成分配的合法草稿可以保存，但不能准备或通过审核。玩家完整分配后，主持人按当前人物卡版本与建卡规则版本通过或退回，并可附反馈。开局时服务端再次检查所有玩家的分配、审批版本、在线与准备状态，不信任客户端提供的角色身份或审批标记。

完整卡片保存及准备阶段的资源／物品修改会使该卡审批失效并取消准备。正式演出禁止换整张卡，允许修改资源与物品，主持人还可通过「角色调整」记录属性／技能的长期调整和临时效果；返回准备阶段后重新审核。规则变更、返回准备、主持权移交或主动离开后的继任会重置审核与准备。旧存档缺少审核元数据时迁移回准备阶段；旧人物卡缺少 `creation` 时可作为草稿导入，补齐分配来源后才能重新审核。局内调整保留原始分配，制卡范围仍校验原始记录；导入及再次审核时会展示全部修正。详见[局内调整说明](CHARACTER-ADJUSTMENTS.md)。

主持人席位不能加载或编辑自己的玩家人物卡，不参加玩家分配与审核。升任主持人前已有的玩家卡会保留，但在主持期间不用于角色检定或先攻；以后成为玩家时仍须重新审核。主持人通过独立资料卡或手填目标代投 NPC，不需要假装玩家来创建 NPC。

## CoC NPC／怪物资料卡

主持人卡库与调查员 `Character` 分开，使用 `documentType: keeper-card`（合集为 `keeper-collection`）。每房最多 200 张卡；支持手填、批量保存、删除、JSON／Markdown 导入导出与存档恢复，单次批量上限 8 MiB。D&D 房间拒绝该 CoC 卡库操作。

资料卡可记录属性值及骰式、HP／MP、护甲、移动、伤害加值、体格、攻击、技能、特殊能力、理智损失和私人笔记。未知或不适用的属性可为 `null`；怪物属性可以超过 100，技能及攻击目标可超过普通调查员边界。手填数据受资料卡格式的有限数值和长度边界校验，不套调查员的职业点、兴趣点、熟练名额或建卡审核。属性骰式支持如 `3d6*5`、`(2d6+6)*5`；攻击伤害和能力描述由 KP 裁定，不自动执行完整怪物战斗或死亡规则。

路人、联络人与「雾岸猎影」模板是本项目原创便捷示例，并非官方固定 NPC／怪物数据。神话生物、神祇、传统恐怖生物、野兽等分类参考 [Chaosium Bestiary](https://cthulhuwiki.chaosium.com/bestiary/)；空白分类模板不附带官方怪物数值，没有自动平衡档位，使用者须按有权使用的规则书或模组填写。

房间卡库只在当前主持人的加入、重连与状态广播中发送。玩家和旧主持人的新快照始终为空数组，修改权限同样由服务端验证；主持权移交或继任时卡库随房间保留。导出文件仍由导出者自行保管。

## 更新与重掷

CoC 制卡器的「属性与状态」页提供可选的**属性点上限**，默认关闭，建议值为 500，可设为 195–720 的整数。总和采用八项属性（STR、CON、SIZ、DEX、APP、INT、POW、EDU），**不含幸运**；开关和数值保存在当前浏览器，下次新建卡也会沿用。启用后只生成不超过上限的骰点，各项仍是原骰式可得到的 5 的倍数；例如上限 503 时总和最多为 500。重掷次数不限，最低合法总和 195 也可直接生成。

房间内若主持人设置了「八项属性总和（不含幸运）」范围，制卡器直接锁定使用该上限，个人开关与数值不影响本房间，也不会被房间设置覆盖。新建和重掷同时遵守主持人的总和下限、各项属性范围。没有房间总和限制时才使用个人上限。无法满足骰式时禁止重掷并提示原因，保留当前卡片；新建时显示明确标记的手填底稿。导入及更改上限不追溯改写已有数值；服务端仍按最终卡片校验并要求审核通过。

超限卡片可选择「按比例降低」或「重新掷骰」。比例降低按 `floor(原属性 × 上限 ÷ 原总和 ÷ 5) × 5` 计算八项属性，幸运保持不变，操作前显示预计总和。它属于手动调整，不是重新生成原骰式结果；因向下取整，最终总和可能略低于上限。若取整后低于主持人的总和下限、违反任意单项范围或出现 0，则不应用任何修改，提示改用重掷或手动调整。属性相关基础技能、HP／MP 上限随之重算，当前资源只在超过新上限时降低，不自动恢复或重置 SAN；职业与兴趣点分配记录保留，但预算可能变少，须复核后重新提交审核。年龄修正仍由用户按规则填写。

`deriveCharacter(character)` 返回新对象：CoC 的资源上限根据属性重算，D&D 保留手填 HP 上限与 AC。更新属性或神话技能时，**当前 HP、MP、SAN 不会自动回升**，只在超过新上限时向下截断。编辑器先用 `syncAllocation` 按当前属性基础值与已记录的分配点数重算技能；CoC 的闪避和母语基础随 DEX、EDU 更新。导入和服务端验证不自动改写分配记录或最终值，不一致的卡片会被要求修改。

`rerollAttributes(character)` 是制卡期的主动重置：重投属性，补满 HP、MP，将 SAN 设为新 POW（受上限约束）；保留身份、笔记、物品、词条和熟练项。CoC 闪避、母语保留高于旧基础的已分配点数并换用新基础。D&D 重新给出临时 HP 与无甲 AC，需要再次按职业／装备校正。进行中的角色状态不应通过重掷来恢复。

词条是本项目原创的性格、动机与牵挂提示，不产生数值加成。刷新次数不限，也不会改动属性。

## 骰子与检定 API

所有会改变房间记录的随机结果应由服务端生成。`rollDice(expression, rng?)` 使用封闭语法解析，支持 `d20`、`2d6+3`、`1d8+1d4-2`、负号和整数项，不执行任何输入代码。每次最多 100 颗骰子、每颗 2–1000 面、表达式 120 个字符；固定修正的每项及累计绝对值最多 10000。不支持乘除、括号、爆骰、保留骰和条件语法。

默认随机源使用 Web Crypto 的无偏拒绝采样。可注入 `(sides: number) => number` 进行可复现测试；随机源必须返回 1 至 sides 的整数。

`rollCheck(rule, character, request, rng?)` 返回原始候选骰、选中骰、调整值、总值、目标和结果。D&D 的 `request.modifier` 是属性／技能／豁免的额外修正，攻击时是完整攻击加值。D&D 以 `request.dc` 为目标。CoC 使用人物技能、属性或 SAN，显式的 `request.target` 会覆盖卡片值；KP 手填 NPC／怪物目标可超过 100（工具边界为 100000），困难与极难阈值不截断，100 仍为大失败。普通理智检定目标最多 100。`edge: advantage/disadvantage` 分别表示一颗奖励／惩罚骰。CoC 不读取 `dc` 和 `modifier`；返回的 `success` 只表示至少普通成功，具体难度由 KP 对照 `outcome` 裁定。

## 人物卡文件

可导出 UTF-8 JSON 或结构化 Markdown。Markdown 包含可读摘要与一个 `json` 代码块，重新导入时以代码块为准。姓名、职业须完成后才可导出、导入和准备；文件不含房间会话凭据或 Gemini 密钥。

数据对应 `shared/types.ts` 中的 `Character`，当前 `schemaVersion` 为数字 `1`：

| 字段                                 | 约定                                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `rule`                               | `dnd` 或 `coc`；必须与目标房间一致                                                                                                               |
| `attributes`                         | D&D: `str,dex,con,int,wis,cha`；CoC: `str,con,siz,dex,app,int,pow,edu,luck`                                                                      |
| `skills`                             | CoC 使用账本计算后的最终百分比；D&D 使用属性、熟练和专精计算的加值                                                                               |
| `creation`                           | 可选分配来源记录；CoC 包含八项职业技能、职业公式与两类点数，D&D 包含职业／背景／种族／替代／额外熟练和专精。缺少时仅作为旧卡草稿，不能准备或审核 |
| `proficiencies`                      | D&D 格式如 `skill:acrobatics`、`save:dex`；不允许重复                                                                                            |
| `hp/maxHp`、`mp/maxMp`、`san/maxSan` | 当前值和上限分开保存；当前值不可超过上限                                                                                                         |
| `items`                              | 每项含唯一 `id`、`name`、整数 `quantity`、`notes`                                                                                                |
| `createdAt/updatedAt`                | ISO 8601 时间戳                                                                                                                                  |

文件最多 256000 个字符。导入拒绝未知版本、规则不匹配、缺少字段、多余顶层字段、字符串伪装的数字、非法对象键、过深结构和超限数组。D&D 属性可记录 1–30，等级 1–20；CoC 人物属性 1–100、技能 0–100（神话最多 99）。这是普通人物卡的录入边界，不用于记录超人类怪物。正文、物品和词条都有长度限制。数值范围合法不等于分配点数、族裔、职业或年龄修正已经符合本团规则。

`adjustments` 是可选的局内修正字段，包含 `permanent` 长期变化和 `temporary` 临时效果。原始 `attributes`、`skills` 和 `creation` 不会被生效数值覆盖；无此字段的旧卡仍可使用。字段定义及叠加方式见[局内调整说明](CHARACTER-ADJUSTMENTS.md)。

## 数据块与战斗记录

D&D 的主持人资料使用 `dnd-statblock`、`dnd-collection` 与提取简式 `dnd-source`，详见 [D&D 数据块格式](DND-STATBLOCKS.md)。它与 CoC 资料卡、玩家人物卡分别存储。

`Room.encounter` 保存独立参战个体、当前回合与版本号。NPC／怪物加入时深复制来源资料，后续编辑或删除模板不影响现有个体。玩家 HP 与房间人物卡同步；主持人编辑中发生其他状态更新时，需重新载入，避免覆盖新记录。

参战个体、检定、资源与伤势记录的操作及裁定边界见 [战斗辅助操作说明](COMBAT.md)。本场记录最多 60 位，每次可从模板加入 1–20 位。未知敏捷的个体需补填敏捷或手填行动值后才能排定。
