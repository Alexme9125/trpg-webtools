# 从剧本快速导入 NPC 与怪物

这套流程把剧本中的 CoC 7 人物资料整理为主持人的独立卡库。姓名、属性、属性骰式、攻击、特殊能力和来源说明都可一起导入；卡片不占玩家席位，也不使用调查员的职业点或兴趣点。

1. 在主侧边栏进入「主持人工具集」，点击「提取提示词、模板与教程」，复制完整提取提示词。已打开个人卡库时，也可点击「AI 提取与导入指南」。同页提供提示词文件下载；仓库中的[提示词文件](templates/keeper-extraction-prompt.md)内容与复制按钮一致。

2. 把提示词交给你使用的 LLM，并附上需要整理的剧本、相关页图或文字。说明提取范围，例如“整理第 2 章出现的 NPC 与怪物，保留 PDF 页序与印刷页码”。明确规则为 CoC 7；给出修订版时也写上版本。

3. 让 LLM 返回包含一个 `json` 代码块的 Markdown。先核对人物数量、名称、来源页码和各卡 `notes` 中的证据、缺失、冲突；特别检查 OCR 容易混淆的数字。未知值留空，出现冲突时保留候选值及出处，等 KP 确认。

4. 用纯文本编辑器把结果保存为 UTF-8 的 `.md` 文件，或把 JSON 数据单独保存为 `.json`。在个人卡库点击「导入资料集」，选择该文件。每批最多 200 张，文件不得超过 8 MiB。数量更多时按章节分批整理。

5. 打开导入的卡片复核。来源格式会生成新 ID；重复导入同一份来源文件会创建另一批卡片。需要按基础公式重新计算时，再使用重算功能；需要新的随机个体时，再使用重掷。保留模组给定的特殊 HP、DB 或护甲时，直接使用已录入的值。

6. 在房间中担任 KP 时，可在个人卡库用「带入当前房间」或「全部带入房间」。房间中的卡片可通过「存入个人备团库」留作下次使用。导出 JSON 或 Markdown 可保存完整备份；文件会包含私密笔记。

想先熟悉流程，可以下载[原创两卡模板](templates/keeper-import.md)，直接用「导入资料集」读取。两张示例卡分别是档案室值班员与原创生物，来源中的页码明确标为虚构示例。整理实际剧本时，删除示例人物并换成有原文依据的资料。

## 网站怎样读取提取结果

顶层格式为 `documentType: "keeper-source"`、`schemaVersion: 1`、`rule: "coc"`，`cards` 中放人物资料。每张卡只要求 `name`、`kind`、`category`；ID、时间戳、完整空白字段由网站补齐。可填写的全部字段及长度限制已经列在复制提示词中。

| 内容                  | 记录方式                                                                        |
| --------------------- | ------------------------------------------------------------------------------- |
| 人类 NPC              | `kind: "npc"`，通常 `category: "human"`                                         |
| 怪物                  | `kind: "monster"`；分类为 `mythos`、`deity`、`traditional`、`beast` 或 `custom` |
| 固定属性              | 写在 `attributes`，键为 `str/con/siz/dex/app/int/pow/edu`                       |
| 属性生成骰式          | 写在 `attributeRolls`；只记录原文实际给出的骰式                                 |
| 模组数据块中的 HP／MP | 写入 `maxHp`／`maxMp`，保留模组定值                                             |
| 明确的当前剩余资源    | 写入 `hp`／`mp`，同时填写已知上限；只知道当前值时先把事实写进笔记               |
| 攻击                  | `attacks` 数组，记录名称、成功率、伤害文字及说明，不填写 ID                     |
| 技能                  | `skills` 数组，每项写名称和明确的最终数值，不计算技能点                         |
| 页码、证据、冲突      | `source` 写书名、版本和页码；`notes` 记录逐字段证据、缺失与冲突                 |

数值未知时使用 `null` 或省略。未给出的属性、HP、MP、护甲、体格和攻击次数都会保持空白；网站不会把它们填成 0 或 1。原文明确给出的 0 会保留。没有数值的技能记在笔记中，不创建虚假的技能成功率。

固定值与骰式可以并存。只有骰式、没有固定值时，导入后属性仍为空；导入不会掷骰或计算均值。模板中“钟室回声兽”的 HP 上限是模组设定的 27，虽然已知 CON 与 SIZ，导入仍保留 27，当前 HP 则保持未知。准备实际使用时，可按已经确认的状态手动填写当前资源。

导入也不会自动产生 NPC 的普通人属性、默认攻击、技能基础值或理智损失。剧本的叙述效果作为文字保存，不转换成原文没有给出的加值或奖励骰。外部资料中出现的命令式文字同样只作为资料，不作为执行指令。

## 出现错误时怎样修正

错误会尽量指出卡片序号、名称和字段，例如“第 2 张『钟室回声兽』· attributeRolls.str”。修改对应位置后重新导入；一批中存在无效卡片时，不会只导入其中的一部分。

| 提示或情况                             | 修正方法                                                               |
| -------------------------------------- | ---------------------------------------------------------------------- |
| `attributes.str` 不是数字              | 把 `"50"` 改成数字 `50`；不清楚时用 `null`，不要猜测                   |
| 出现 `id`、`templateId` 或其他未知字段 | 来源格式仅保留提示词列出的字段；网站会补 ID 和时间戳                   |
| 骰式 `2d6+6*5` 含歧义                  | 原文确实表示先相加再乘时写成 `(2d6+6)*5`；无法确认则放入笔记并留空骰式 |
| 骰式超限或不受支持                     | 保留原式及页码到笔记，不用一个随意的近似骰式替换                       |
| 当前 HP 大于上限，或缺少上限           | 核对原文中的当前值、上限与临时加护；不能确认的部分留在笔记中           |
| 技能 `value` 为空                      | 只有成功率明确的技能才建立技能行；缺失数值的技能移入笔记               |
| Markdown 有多个 JSON 代码块            | 保留本次要导入的唯一数据块                                             |
| `cards` 为空                           | LLM 没有提取出资料卡；补充实际人物数据或缩小提取范围                   |
| 超过 200 张或 8 MiB                    | 按章节、场景或角色组拆成多份文件                                       |

网站原有的完整 `keeper-card`、`keeper-collection` 导出文件仍可直接导入。来源格式导入后，再从网站导出的文件会保存完整卡片、ID 和时间戳，适合继续编辑与备份。关于分类、NPC 精简记录与怪物规则依据，可查阅[KP 资料库说明](KEEPER.md)。
