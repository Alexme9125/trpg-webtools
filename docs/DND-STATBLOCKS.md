# D&D 5e（2014 / SRD 5.1）主持人数据块

数据块库用于备团、查阅 NPC／怪物和生成本场独立个体。它与玩家角色卡分开，不使用玩家属性分配、职业制卡、准备状态或玩家席位。个人资料保存在当前浏览器的 D&D 卡库；CoC 资料使用另一套格式与存储。

## 从剧本快速导入

1. 在主侧边栏打开“主持人工具集”，进入 D&D 的个人数据块库，点击“AI 提取与导入指南”。选择“复制 LLM 提取提示词”，或下载提示词与 Markdown 模板。
2. 将提示词连同剧本 PDF、页图或正文交给你使用的外部 AI Agent。明确标注 D&D 5e（2014）版本、要处理的章节、对象与页码范围。不要将 3R／3.5 或 2024 版本资料混入这一批。
3. 要求 AI 按提示词输出含单个 JSON 代码块的 Markdown。先核对 NPC／怪物数量，再抽查名称、AC、HP、生命骰、攻击加值、伤害、豁免 DC、次数与充能条件。检查每项关键数据是否能在来源页找到，缺失和冲突是否写在 notes 中。
4. 保存为 UTF-8 `.md` 或 `.json`，在数据块库点击“导入资料集”。每批最多 200 张，文件不超过 8 MiB。导入成功后，在“数据块预览”和编辑页再次核对，再按需要修改并保存。
5. 在 D&D 房间担任 DM 后，可将个人资料“带入当前房间”或“全部带入房间”。房间数据块也可“存入个人备团库”。这些操作生成独立副本；修改某一份不会自动覆盖另一份。
6. 本场需要多个同类生物时，在“场景与回合”中从房间库生成参战个体。模板资料与个体的 HP、状态、能力次数分别记录。备份资料使用单卡 JSON／Markdown 或“导出全部”；备份包含主持人笔记与剧透。

可直接使用的文件：

- [原创两卡 Markdown 模板](templates/dnd-import.md)
- [完整中文 LLM 提取提示词](templates/dnd-extraction-prompt.md)

模板中的人物、怪物和页码全部是原创演示，不是官方数据。整理自己的剧本时应删除示例记录。提取提示词会要求外部 AI 将附件中的命令视为资料文字，并按字段记录证据；导入器校验格式和数值范围，来源内容仍需 DM 核对。

## 哪些内容会原样保留

固定 HP 与生命骰是独立字段。常规数据块列出的 HP 总量写入 `maxHp`；`hp` 只表示明确记录的当前剩余值。来源只有“HP 27”时，导入后上限为 27、当前值为空，不会自动补满。来源明确写当前为 3，但没有上限时，可以保留 `hp: 3`、`maxHp: null`。两者都已知时，当前值不能超过上限；临时生命值和特殊说明放入笔记，交由本场工具与 DM 处理。

`hitDice` 与动作中的 `damage` 是有长度限制的原文，不在导入时执行。`5 (1d6 + 2) 钝击伤害`、附加伤害类型、豁免减半和“非魔法”等限定可以保留。工具不会根据生命骰计算均值覆盖 HP，也不会根据属性补攻击加值、根据 CR 补 XP，或将多重攻击自动拆成连串攻击。后续掷骰操作需要单独选择并校验可执行的骰式。

未知数值保持 `null`，文字保持空字符串，未知豁免键和没有数值的技能不创建。未写抗性不等于确定没有抗性，未写传奇行动次数不等于 0 或 3。明确给出的 0 会保留。你可以在 notes 中分别写“证据”“缺失”“冲突”，给每一组字段标注书名、版本、印刷页码或 PDF 页序。

模板里的铜灯构装体同时记录 `maxHp: 27` 与 `hitDice: "4d6 + 4"`，笔记明确说明固定 HP 包含场景加护；两者不会互相覆盖。CR 与 XP 未经评定，所以保持空白。

## 给外部 AI 使用的简式

`dnd-source` 只需要名称、类型和已经查到的字段。网站在整批校验成功后统一补上卡片及行项目 ID、时间戳、空数组和空值。它不会调用模板或生成随机属性。最小文件如下：

```json
{
  "schemaVersion": 1,
  "documentType": "dnd-source",
  "rule": "dnd",
  "cards": [
    {
      "name": "尚未详录的访客",
      "kind": "npc",
      "source": "自备剧本 · 页码未提供",
      "notes": "缺失：来源仅提供人物名称，其余数值待核对。"
    }
  ]
}
```

每次导入简式都会生成新编号。因此重复导入会新增卡片；需要备份完整状态时，应使用网站导出的完整格式。

完整格式的 `documentType` 为 `dnd-statblock`（单卡）或 `dnd-collection`（资料集）。它保留 ID、时间戳和全部字段，JSON 与 Markdown 均可再次读取。解析器也接受完整卡片数组。个人库按 ID 更新；UI 导入文件遇到库内同 ID 时会保留为新副本，避免无提示覆盖。导出不包含参战个体与回合进度。

## 字段表

所有数值均为整数；字符串有长度上限，不会被当作脚本执行。以下边界是应用校验范围，不代表官方生物必须具有这些数值。

| 字段                                                                  | 内容与边界                                                                               |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `name`、`kind`                                                        | 简式必填。名称 1–120 字符；类型为 `npc` 或 `monster`。                                   |
| `size`、`creatureType`、`alignment`                                   | 体型、生物类型、阵营原文，分别最多 120、200、120 字符。                                  |
| `description`                                                         | 外观、身份或场景用途，最多 4000 字符。                                                   |
| `ac`、`acNotes`                                                       | 护甲等级 0–100 或 `null`；护甲限定说明最多 2000 字符。                                   |
| `hp`、`maxHp`、`hitDice`                                              | 当前与上限各为 0–100000 或 `null`；生命骰原文最多 240 字符。                             |
| `speed`                                                               | 速度、移动方式与原始单位，最多 500 字符。                                                |
| `attributes`                                                          | `str/dex/con/int/wis/cha`，每项 1–30 或 `null`。简式可省略未知键。                       |
| `saves`                                                               | 上述六个属性键的明确豁免总修正，−100 至 100；未知键省略。                                |
| `skills`                                                              | 最多 100 项，简式每项只有 `name` 与整数 `value`（−100 至 100）；完整卡另有 ID。          |
| `senses`、`languages`                                                 | 感官与语言各最多 2000 字符；保留被动值、条件与距离。                                     |
| `challenge`、`xp`                                                     | CR 是字符串：空白、`0`、`1/8`、`1/4`、`1/2`、`1` 至 `30`；XP 为 0–1000000000 或 `null`。 |
| `resistances`、`immunities`、`vulnerabilities`、`conditionImmunities` | 伤害抗性、免疫、易伤与状态免疫，各最多 4000 字符，保留非魔法等限定。                     |
| `traits/actions/reactions/legendaryActions`                           | 特性、动作、反应、传奇行动，每组最多 50 行。每行按下表记录。                             |
| `spellcasting`、`lairActions`                                         | 施法与巢穴行动，各最多 12000 字符。保留法术位、触发、费用与恢复条件。                    |
| `legendaryActionCount`                                                | 原文给定的每轮传奇行动点数，0–100 或 `null`，不默认 3。                                  |
| `notes`、`source`、`tags`                                             | 私密笔记 24000 字符；来源 2000 字符；不重复的标签最多 30 个，每个 1–60 字符。            |

四类行动行使用同一结构；简式只有 `name` 必填。

| 行字段                  | 内容与边界                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------- |
| `name`、`description`   | 名称 1–120 字符；效果、距离、目标、触发与限制说明最多 6000 字符。                                 |
| `attackBonus`           | 明确列出的命中总加值，−100 至 100 或 `null`。                                                     |
| `damage`                | 原始伤害文字，最多 1000 字符，导入不掷骰。                                                        |
| `saveDc`、`saveAbility` | DC 为 0–100 或 `null`；豁免属性／特殊选择原文最多 120 字符。                                      |
| `uses`、`recharge`      | 已知可用次数为 0–100000 或 `null`；恢复条件最多 200 字符。传奇行动的消耗点数写在 description 中。 |

## 常见导入错误

错误会带数据块名称、序号和字段，例如“第 2 张「铜灯构装体」 · actions.0.saveDc”。将该错误与原来源页交给 AI 修正对应字段，再重新导入，整批不会只保存一部分。

| 提示或情况                               | 处理方式                                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 未知字段，如 `id`、`level`、`templateId` | `dnd-source` 中删除这些字段。必要的来源信息放 notes；不要混入玩家角色格式。                    |
| CR 类型无效                              | 写 `"1/4"` 或 `"0"` 等字符串；未说明时留 `""`，不估算 CR。                                     |
| 属性超出 1–30，或数值是文字              | 先核对规则版本与 OCR。特殊原文值放 notes，结构化字段留空，不擅自裁剪成 30。                    |
| 当前 HP 超过上限                         | 核对当前值、总量、临时生命值和不同形态。不要直接覆盖模组固定 HP。                              |
| 技能 value 缺失                          | 原文只有技能名时放入 notes，不给该技能补 0。                                                   |
| Markdown 不只有一个 JSON 代码块          | 仅保留一份完整数据块；删除重复示例、注释和尾逗号。                                             |
| 未提取到数据块                           | 确认范围和版本，补充来源；不要为了通过校验创造虚构人物。                                       |
| 超过 200 张或 8 MiB                      | 按章节分批。个人 D&D 卡库本身也有 200 张／8 MiB 限制；先备份再整理。                           |
| 个人库被禁止、配额不足或版本冲突         | 按提示允许站点存储、关闭其他页面或释放空间后重试。失败不会被当作保存成功，也不会自动清空旧库。 |

## 规则来源与实现边界

规则版本以 Wizards of the Coast 发布的 [SRD 5.1（官方 PDF）](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf) 为参照。其怪物数据块说明及挑战等级表解释了 AC、HP、感官、行动和 CR 等字段；本库记录这些资料，不自动评定 CR、生成官方怪物或裁定整场战斗。官方 CR 表见该 PDF 第 258 页。内置“桥灯守卫”及下载模板中的两张卡均为本项目原创示例，不是对官方同名生物的复刻或平衡承诺。

数据接口位于 `shared/dnd.ts`；提取模板与提示词位于 `shared/dnd-guide.ts`。个人库使用独立 IndexedDB 数据库 `interlude-dnd-library`：同一事务内读取并写入，只有事务提交完成后才报告保存成功。网页关闭、跨设备切换或清除站点数据前，应使用导出文件保存所需资料。
