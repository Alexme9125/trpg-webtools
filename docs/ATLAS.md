# 地图册与场景集

## 从外部剧本整理

1. 打开「主持人工具集 → 地图与场景」，选择「提取提示词、模板与教程」。
2. 复制提示词，连同有权使用的剧本 PDF、文字或页图交给外部 AI Agent。告诉它规则、章节、页码和需要整理的范围；此操作不调用站内 Gemini。
3. 让 AI 生成一个 Markdown 文件，内含一个完整的 JSON 数据块。地图记录地点布局、出入口和路线；每个地图可以关联很多场景，也可创建没有地图的独立场景。此处不生成战棋地图图片。
4. 下载 .md 或 .json，在个人地图集中点击「导入地图集」，检查数量、来源和规则后确认导入。文件作为独立副本保存，不覆盖已有原稿。
5. 核对公开描述和主持人笔记。隐藏线索、秘密、检定条件应放入主持人笔记。AI 提取可能出错，尤其要检查是否把剧透放进了公开描述。
6. 创建房间后，以主持人身份打开个人地图集，选择「带入房间」。房间里的资料是独立副本。
7. 在房间桌边工具中打开「地图与场景」，搜索场景、选择地图，查看公开预览与主持人笔记，然后点击「公布此场景」。只有标题和公开描述会出现在所有人的当前场景中。

## 手动整理和复用

「新建地图册」建立一本资料集；「添加地图」建立地点，「添加场景」建立场景。选择地图后创建的场景会自动归属该地图，也可在场景编辑中调整。删除地图会让所属场景变为独立场景，不删除场景内容。修改后点击「保存地图册」，再导出或带入房间。

个人地图集使用当前浏览器的 IndexedDB，最多 50 本、8 MiB。每本最多 50 张地图、300 个场景。刷新可恢复，换浏览器或设备需先导出备份。房间地图集在服务端保存，只有当前主持人能读取和修改，移交主持权后由新主持人接手。

Markdown 和 JSON 导出均可再次导入，包含主持人笔记。地图资料不会自动发布。当前场景只是公开文本的副本，删除地图集不会清空已公布的场景。

## 文件结构

外部 AI 使用 `documentType: "atlas-source"`、`schemaVersion: 1` 和 `atlases` 数组。`maps[].key` 必须在本册唯一，`scenes[].mapKey` 引用该 key 或为 null。未知值使用空字符串，可选字段会补齐为空，不自动补剧情或规则数值。

网站导出使用 `interlude-atlas-library`，其中每册使用 `interlude-atlas`，带有持久编号和时间。导入要求版本、字段类型、引用关系和容量均有效，整批成功后才保存。出现格式错误时原库保持不变。
