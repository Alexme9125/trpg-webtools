# 全局存档与续团

## 跑到一半，怎样保存

1. 主持人在房间右侧工具中打开「全局存档」。手机上先切换到「局内工具」。无需返回准备阶段。
2. 查看房间、规则、角色、记录数量和备团资料摘要。
3. 「导出图片（仅保留路径引用）」默认开启：上下文记录对应图片在服务器 `IMAGE_DIR` 中的路径，ZIP 只保存恢复引用，不包含或下载原图。可选填描述，以便原图过期后仍能阅读线索。关闭开关时，须为每张图片填写替代描述；恢复后只显示这些文字。展开文件名可预览原图，图片较多时分页填写；成功导出的描述可在下次复用。
4. 点击「选择保存位置并导出 ZIP」，选定文件名和文件夹。此时截取房间最新状态，并生成压缩包；之后的新消息和操作不在这个快照中。若关闭图片开关且填写期间新增图片，先刷新资料并补上描述。
5. 不支持保存位置选择的浏览器显示「下载全局存档 ZIP」。在浏览器的下载设置中启用“下载前询问保存位置”，或从下载列表移动文件。网页无法强制 Safari 等浏览器显示文件夹选择器；支持此 API 的桌面 Chrome / Edge 可直接选择保存位置，且需要 HTTPS 或 localhost。

取消位置选择不会提交导出；写入失败时会显示错误并允许重试。使用浏览器下载方式时，请在下载列表确认文件已保存。

## 下一次继续

1. 在首页选择与存档相同的规则。
2. 在「创建房间」页填写主持人称呼，点击「从全局存档续团」，选择 ZIP，无需解压。
3. 核对摘要与原来的阶段，点击「恢复存档，继续故事」。普通房间配置 JSON / Markdown 只复用设置；全局 ZIP 会恢复角色及整个进度。
4. 主持人会自动看到续团席位清单。分别把新房间码和对应的席位恢复码发给每名玩家，不要把所有人的恢复码发到公共聊天中。
5. 玩家选择相同规则，在「加入房间」中填写新房间码、称呼和自己的席位恢复码，即可回到原来的角色。每个恢复码只可使用一次；进入后仍通过本浏览器的正常会话凭证重连。

新的房间码、会话令牌和席位恢复码都会重新生成。旧房间和旧凭证不会被覆盖或复用。主持人可再次打开「全局存档」查阅尚未认领的席位。

原来在进行中的房间仍保持进行中；准备阶段的房间保留原审核与准备状态，等成员认领上线后按正常规则开始。角色数值、临时修正是否启用、HP / MP / SAN、物品、当前场景、遭遇个体、状态与剩余次数、回合及当前行动者都会恢复。不会自动重掷先攻或清除临时效果。

## 压缩包里有什么

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 格式版本、导出时间、图片开关及各文件 SHA-256 校验和 |
| `room.json` | 房间配置、所有角色与审核、当前状态、房间地图 / 场景库、NPC / 数据块、遭遇进度和完整可用事件历史 |
| `context.md` | 可直接阅读或交给外部 AI 的过程记录，含暗骰真实结果、图片的服务端路径或替代描述 |
| `README.md` | 简要恢复说明 |

存档包含主持人私密备团资料和暗骰真实结果，应由主持人保管。开启图片开关时，在原服务器恢复可读取保留期内的图片；图片过期、原服务器不可用或引用失效时，在原消息位置显示占位符。关闭时只显示主持人填写的文字，无法从文字还原图片。浏览器个人备团库中尚未带入此房间的资料不属于此房间存档；可在各资料库独立导出。

格式版本为 2，仍兼容版本 1 的纯文字图片存档。不含服务器 API 密钥、登录令牌、席位恢复码或图片文件。每个存档只支持对应规则；版本、内容校验、状态引用和大小不合法时会拒绝导入，不创建半成品房间。ZIP 上限 32 MiB，解压后 `room.json` 上限 64 MiB、`context.md` 上限 28 MiB；超限会报错，绝不截断记录。校验和用于发现损坏，不是存档来源认证。

## 记录与暗骰

服务端保存全量记录；正常页面首先加载最近 300 条，可点击「加载更早记录」逐页查看。全局存档导出所有可用记录；聊天区的 Markdown 小按钮仅导出当前已载入的部分。

主持人暗骰时，玩家可以看到谁在何时投骰及骰式 / 检定名称，点数和结果均显示“？”。真实骰面、修正、目标、成功状态和请求标识不会发送给玩家。历史加载和续团重连也使用同样的遮罩。复合 CoC 近战暗骰显示“近战对抗”，不暴露参与者和数值。

旧版本曾只保留最近 300 条，已经删除的历史无法恢复。升级后会保留后续全部记录；遇到可能截断的旧存档，会在导出 / 导入摘要明确提示。

场景更新会在历史中保留当时的公开描述。升级之前未记入日志的场景描述也无法事后补回。房间外进行的语音、文字或其他平台内容，需要参与者自行记入房间，网站无法自动取得。

## 部署说明

- 保持 `DATA_DIR` 可写；完整历史随 `rooms.json` 原子保存。随着长期跑团记录增长，请预留磁盘并定期备份。
- `IMAGE_DIR` 保存原图，`DATA_DIR/images.json` 保存独立的保留时间、删除状态及引用签名信息。备份或迁移时同时保存 `DATA_DIR` 与图片目录；只迁移 ZIP 不会带走图片。路径调整后只要迁移图片目录并保留 `images.json`，原引用仍有效。请勿公开该元数据文件。
- 图片在最后一次游玩结束后保留 14 天，到期自动删除。系统以“进行中的房间返回准备、关闭房间或全员离线”作为结束时间；再次开团会续期，正在游玩的房间引用的图片不会清理。多个续团房间引用同一张图时，按最后结束的一次计算。
- 只查看图片、导出 ZIP、预览存档或仅导入但尚未上线，不会延长保留期。尚未开团的旧图片从上传时间起计时；旧版本没有结束时间时使用本地记录的最后活动时间迁移。
- 服务启动时及运行期间每分钟检查到期图片；停机期间到期的图片在下次启动时删除。清理机制独立于房间的 7 天期限，即使旧房间先过期，图片仍保留到自己的截止时间。已删除的原图无法通过导入旧存档复活，恢复时显示占位符，补充描述仍保留。
- 清理仅针对本服务管理的图片文件，不扫描子目录或跟随符号链接。请为部署用户保留文件删除权限。
- 离线房间默认 7 天无活动后清理，长期暂停前请导出 ZIP。
- Nginx / OpenResty 的 `client_max_body_size` 应至少为 `32m`，以允许 ZIP 导入；上传时限需覆盖网络传输。ZIP 数据上传、解析和读取历史均有服务端边界，只有主持人能导出完整存档。
